============================================================
                    SATORII — MANUAL MAESTRO
============================================================

Documento central de identidad, diseño, estructura y
convenciones para el desarrollo de la página web de SATORII.

Este archivo debe consultarse antes de crear o modificar
cualquier página, componente, imagen o sección del sitio.


============================================================
1. IDENTIDAD DE SATORII
============================================================

Nombre:
SATORII

Concepto:

SATORII combina:

- Cultura japonesa
- Anime
- Streetwear
- Diseño urbano
- Cultura pop
- Productos coleccionables
- Identidad visual japonesa contemporánea

La página debe sentirse:

- Moderna
- Urbana
- Minimalista
- Premium
- Japonesa sin caer en exceso de elementos tradicionales
- Visualmente fuerte
- Limpia
- Fácil de navegar

5. IMÁGENES
============================================================

Todas las imágenes deben estar organizadas por función.

NO colocar imágenes aleatoriamente en la carpeta principal.

------------------------------------------------------------

/img/productos/

WEBP

producto-nombre-numero.webp

polera-torii-02.webp
polera-torii-03.webp

El header oficial se encuentra implementado mediante:

El header incluye:

- Barra superior
- Instagram
- Envíos a todo Chile
- Logo SATORII
- Navegación
- Colecciones
- Productos
- Ayuda
- Buscador
- Cuenta
- Carrito
- Menú móvil
- Carrito lateral
- Buscador modal
- Header flotante al hacer scroll


COLOR HEADER:

#000000


ROJO:

#EF0930


IMPORTANTE:

Si se modifica el header:

Modificar solamente:

satorii-header.js


No crear versiones diferentes del header para cada página.

satorii-footer.js

- Blanco

9. PRODUCTOS
============================================================

Todos los productos deben utilizar una estructura de datos
consistente.


Ejemplo:

{
    id: "satorii-001",
    name: "Polera Torii",
    price: 24990,
    image: "img/productos/polera-torii-01.webp",
    category: "torii",
    collection: "anime",
    sizes: ["S", "M", "L", "XL"]
}


PROPIEDADES PRINCIPALES:

id
name
price
image
category
collection
sizes


Propiedades opcionales:

description
images
oldPrice
discount
stock
featured
newProduct
colors
tags


============================================================
10. TARJETAS DE PRODUCTOS
============================================================

Las tarjetas deben mantener un diseño limpio y moderno.


Cada tarjeta puede contener:

- Imagen
- Etiqueta NUEVO
- Etiqueta OFERTA
- Nombre
- Precio
- Precio anterior
- Descuento
- Botón / interacción de carrito


INTERACCIÓN HOVER:

Al pasar el mouse:

- La tarjeta puede elevarse ligeramente
- La imagen puede hacer un pequeño zoom
- Puede aparecer una sombra
- El rojo SATORII puede utilizarse como acento


NO exagerar las animaciones.


Las animaciones deben sentirse:

- suaves
- rápidas
- premium


============================================================
11. ANIMACIONES
============================================================

Duración recomendada:

0.2s
0.25s
0.3s


Usar:

ease
ease-out


Evitar animaciones demasiado lentas.


La interfaz debe sentirse rápida.


Para usuarios con:

prefers-reduced-motion: reduce

Las animaciones deben reducirse o eliminarse.

============================================================
15. CARRITO
============================================================

Storage principal:

satorimode_cart


Storage antiguo compatible:

satorii_cart


El carrito utiliza:

localStorage


Debe mantener:

- Producto
- Precio
- Imagen
- Cantidad
- Subtotal


El contador del header debe actualizarse
automáticamente.


EVENTO:

satori-cart-updated


Cuando otro componente modifique el carrito,
debe poder disparar:

window.dispatchEvent(
    new Event("satori-cart-updated")
);


============================================================
16. BÚSQUEDA
============================================================

La búsqueda utiliza:

productos.html?search=


Ejemplo:

productos.html?search=torii


El header ya genera esta URL.


productos.html debe interpretar el parámetro:

search


y filtrar los productos.

============================================================

SATORII NO debe parecer:

- una tienda genérica
- una página llena de colores
- una tienda de dropshipping
- una página saturada de banners
- una página excesivamente japonesa tradicional


Debe sentirse:

STREETWEAR
+
JAPÓN
+
ANIME
+
MINIMALISMO
+
PREMIUM

80px
100px

26. ACCESIBILIDAD
============================================================

Todos los botones deben tener:

aria-label

cuando sea necesario.


Todas las imágenes deben tener:

alt


Los elementos interactivos deben poder utilizarse
con teclado.


Mantener:

focus-visible


No eliminar completamente los indicadores de foco.

28. JAVASCRIPT
============================================================

satorii-footer.js

→ Footer

============================================================
29. CSS
============================================================

Evitar estilos repetidos entre páginas.


Los estilos globales deben ir en:

global.css


Los estilos específicos:

productos.css
producto.css
carrito.css
checkout.css


Los componentes globales:

Header
Footer


deben tener sus propios estilos o estar claramente
organizados.


============================================================
30. CÓDIGO
============================================================

Todo código nuevo debe:

- Ser legible
- Estar comentado cuando corresponda
- Mantener la estructura existente
- No romper funcionalidades anteriores
- Ser responsive
- Mantener #EF0930
- Mantener las rutas existentes
- Evitar dependencias innecesarias


Antes de reemplazar un archivo completo:

revisar qué funcionalidades ya existen.


NO eliminar funciones existentes solamente para
agregar una nueva.

31. IMÁGENES GENERADAS
============================================================

Cuando se genere una imagen para SATORII:

1. Definir primero su función.

2. Definir dónde se utilizará.

3. Definir proporción.

4. Definir nombre del archivo.

5. Guardarla en su carpeta correspondiente.


Ejemplo:


Imagen:

Hero principal

/img/banner/


Nombre:

hero-principal.webp

============================================================
33. BANNERS — REGLAS
============================================================

Los banners deben mantener:

- buena resolución
- composición limpia
- espacio para texto
- buena lectura en móvil
- buena lectura en desktop


No colocar texto importante pegado a los bordes.


Cuando sea posible:

crear una versión desktop
y una versión mobile.


Ejemplo:


hero-principal-desktop.webp
hero-principal-mobile.webp

como texto/vector cuando sea posible.


No deformar el logo.


No cambiar:

- proporciones
- inclinación
- colores
- espaciado


Sin una razón de diseño específica.

40. REGLA PRINCIPAL
============================================================

ANTES DE CREAR ALGO NUEVO:

Preguntar:

¿Esto debería ser un componente reutilizable?


Si la respuesta es sí:

crear un componente global.


Si la respuesta es no:

mantenerlo específico de la página.


La finalidad es evitar tener código duplicado
en todas las páginas.
