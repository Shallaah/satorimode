============================================================
                    SATORII — MANUAL MAESTRO
============================================================

Documento central de identidad, diseño, estructura y
convenciones para el desarrollo de la página web de SATORII.

Este archivo debe consultarse antes de crear o modificar
cualquier página, componente, imagen o sección del sitio.


============================================================
1. IDENTIDAD DE SATORII
============================================================

Nombre:

SATORII


Concepto:

SATORII combina:

- Cultura japonesa
- Anime
- Streetwear
- Diseño urbano
- Cultura pop
- Productos coleccionables
- Identidad visual japonesa contemporánea


La página debe sentirse:

- Moderna
- Urbana
- Minimalista
- Premium
- Japonesa sin caer en exceso de elementos tradicionales
- Visualmente fuerte
- Limpia
- Fácil de navegar

    checkout.html

    regala-satorii.html

El Header oficial es un componente global.


Archivo:

satorii-header.js


No duplicar manualmente el Header dentro de cada HTML.


El Header incluye o puede incluir:

- Barra superior
- Ticker
- Instagram
- Envíos a todo Chile
- Logo SATORII
- Navegación
- Colecciones
- Productos
- Ayuda
- Buscador
- Cuenta
- Carrito
- Menú móvil
- Carrito lateral
- Buscador modal
- Header flotante al hacer scroll


COLOR HEADER:

#000000


TICKER:

#101727


ROJO:

#EF0930


IMPORTANTE:

Si se modifica el Header:

Modificar el componente global.


No crear versiones diferentes del Header para cada página.


Antes de modificarlo:

Revisar todas las funcionalidades existentes.


NO eliminar funcionalidades existentes únicamente para
agregar una nueva.

============================================================
10. TARJETAS DE PRODUCTOS
============================================================


Las tarjetas deben mantener un diseño limpio y moderno.


Cada tarjeta puede contener:

- Imagen
- Etiqueta NUEVO
- Etiqueta OFERTA
- Nombre
- Precio
- Precio anterior
- Descuento
- Botón / interacción de carrito


------------------------------------------------------------
INTERACCIÓN HOVER
------------------------------------------------------------

Al pasar el mouse:

- La tarjeta puede elevarse ligeramente
- La imagen puede hacer un pequeño zoom
- Puede aparecer una sombra
- Puede utilizarse el rojo SATORII como acento


NO exagerar las animaciones.


Las animaciones deben sentirse:

- suaves
- rápidas
- premium


============================================================
11. ANIMACIONES
============================================================


Duraciones recomendadas:

0.2s
0.25s
0.3s


Preferir:

ease
ease-out


Evitar animaciones demasiado lentas.


La interfaz debe sentirse rápida.


------------------------------------------------------------
REDUCED MOTION
------------------------------------------------------------

Para usuarios con:

prefers-reduced-motion: reduce


Las animaciones deben reducirse o eliminarse.

13. RESPONSIVE
============================================================


La página debe diseñarse pensando en:

Desktop
Tablet
Mobile


Los breakpoints deben respetar la arquitectura actual
del proyecto.


Como referencia actual del Footer:

Tablet:

<=1000px


Mobile:

<=700px


Mobile pequeño:

<=420px


IMPORTANTE:

No asumir que todos los componentes deben utilizar
exactamente los mismos breakpoints.


Antes de modificar breakpoints globales:

Revisar:

- style.css
- animations.css
- Header
- Footer
- Componentes afectados


Nunca diseñar únicamente para Desktop.

============================================================
15. CARRITO
============================================================


Storage principal:

satorimode_cart


Storage antiguo compatible:

satorii_cart


El carrito utiliza:

localStorage


Debe mantener:

- Producto
- Precio
- Imagen
- Cantidad
- Subtotal


El contador del Header debe actualizarse
automáticamente.


EVENTO:

satori-cart-updated


Cuando otro componente modifique el carrito,
puede disparar:


window.dispatchEvent(
    new Event("satori-cart-updated")
);


============================================================
16. BÚSQUEDA
============================================================


La búsqueda utiliza:

productos.html?search=


Ejemplo:

productos.html?search=torii


El Header genera esta URL.


productos.html debe interpretar:

search


y filtrar los productos correspondientes.

satorii-footer.js

→ Footer

============================================================
29. CSS
============================================================


Evitar estilos repetidos entre páginas.


Actualmente la arquitectura utiliza principalmente:

style.css

animations.css


y archivos específicos cuando sean necesarios.


Ejemplos:

productos.css
producto.css
carrito.css
checkout.css


IMPORTANTE:

No crear automáticamente un archivo llamado:

global.css


si la arquitectura actual no lo necesita.


Antes de crear un archivo CSS nuevo:

1. Revisar style.css.
2. Revisar animations.css.
3. Revisar estilos existentes.
4. Determinar si el componente puede reutilizar
   estilos existentes.


Los componentes globales:

Header
Footer


deben tener sus estilos claramente organizados.


============================================================
30. CÓDIGO
============================================================


Todo código nuevo debe:

- Ser legible
- Estar comentado cuando corresponda
- Mantener la estructura existente
- No romper funcionalidades anteriores
- Ser responsive
- Mantener #EF0930
- Mantener #101727 para Footer y Ticker oficiales
- Mantener las rutas existentes
- Evitar dependencias innecesarias


Antes de reemplazar un archivo completo:

revisar qué funcionalidades ya existen.


NO eliminar funciones existentes solamente para
agregar una nueva.


Antes de modificar un componente global:

revisar qué páginas dependen de él.

40. REGLA PRINCIPAL
============================================================


ANTES DE CREAR ALGO NUEVO:


Preguntar:


¿Esto debería ser un componente reutilizable?


Si la respuesta es sí:


crear o reutilizar un componente global.


Si la respuesta es no:


mantenerlo específico de la página.


La finalidad es evitar tener código duplicado
en todas las páginas.

------------------------------------------------------------

1. Revisar el código actual.

2. Identificar las funcionalidades existentes.

3. Identificar las páginas afectadas.

4. Mantener compatibilidad.

5. Modificar únicamente lo necesario.

6. Comprobar responsive.

7. Comprobar que no se rompan otros componentes.
