============================================================
                    SATORII — MANUAL MAESTRO
                    VERSIÓN ACTUALIZADA
============================================================

Documento central de identidad, diseño, estructura,
convenciones y estado del proyecto web SATORII.

Este manual debe consultarse antes de crear o modificar
cualquier página, componente, imagen, estilo o funcionalidad.

actual de SATORII y tiene prioridad sobre documentación
antigua o nombres de archivos que ya no existen.

============================================================

Las imágenes deben organizarse por función.

REGLAS:

- Preferir WEBP para imágenes optimizadas.
- Mantener nombres consistentes.
- Evitar duplicados innecesarios.
- No cambiar rutas existentes sin revisar referencias.


PRODUCTOS:

/img/productos/

producto-nombre-01.webp

COLECCIONES:

relacionadas con su función.


ICONOS:

Siempre que sea posible:

- SVG
- CSS

si pueden realizarse mediante SVG o CSS.

============================================================
16. CARRITO
============================================================

El carrito utiliza localStorage.


STORAGE PRINCIPAL:

satorimode_cart


STORAGE ANTIGUO COMPATIBLE:

satorii_cart


El sistema debe mantener:

- Producto
- Precio
- Imagen
- Cantidad
- Subtotal


El contador del Header debe actualizarse
automáticamente.


EVENTO:

satori-cart-updated


Cuando otro componente modifique el carrito puede utilizar:

window.dispatchEvent(
    new Event("satori-cart-updated")
);


El sistema del carrito está separado en:

/js/cart.js


y la interfaz global del carrito se integra con:

/js/header.js

¿Esto debería ser un componente reutilizable?

Si la respuesta es no:
